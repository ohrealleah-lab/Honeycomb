# Honeycomb Android — CLAUDE.md

Jetpack Compose port of the **Honeycomb Card Suite** (Klondike, Beecell, Spider, Video Poker, Blackjack, Honeycomb) in the monorepo's `android/` folder. Claude is the only developer working on it now (Gemini no longer contributes).

**Parity: Mac is the source of truth** — game logic here is a hand port of `shared/` (Swift), not shared code, so every rules fix must be mirrored by hand. The settled product rules live in `mac/CLAUDE.md` → "Product rules". Android is a mobile platform: Video Poker/Blackjack are hard-locked free play (no betting, credits or money stats), Klondike has no Vegas scoring, there's no Reset Stats button, and Beecell is 1-deck only.

## Build & test
```bash
./gradlew :app:assembleDebug        # debug APK
./gradlew :app:testDebugUnitTest    # JVM unit tests
```

## Tests
- **Parity vectors** (`src/test/.../*VectorTests.kt`) replay JSON generated by Mac (`shared/**/TestVectors`, regen with `cd mac && HONEYCOMB_REGEN_VECTORS=1 make test`) — Honeycomb capture rules/AI, Video Poker scoring, card database.
- **ViewModel tests** extend `ViewModelTestBase` (`src/test/.../TestSupport.kt`): a Main dispatcher on a virtual clock (advance `clock.scheduler` to run delays), throwaway DataStore files, and the real banner catalog read from `shared/Honeycomb/Resources/`. ViewModels keep state private, so tests set boards up via `privateFlow(vm, "_state")`. Add a test here whenever a rules fix lands on Android.

## Notes
- All user-visible text goes through `tools/Honeycomb_Localization.xlsx` → `python3 tools/generate_localization.py` (regenerates `StringKey.kt`/`Strings.kt` with the other platforms). Use `tr(StringKey.X)` in composables.
- `BannerCatalog` takes a JSON loader; the app passes its assets copy via the `Context` constructor.
- In-progress games (all six) are saved to DataStore and restored at launch; the Klondike Vegas bankroll does *not* carry over.
